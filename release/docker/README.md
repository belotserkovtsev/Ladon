# Ладон в контейнере

Контейнер здесь — не просто упаковка. Наборы адресов живут внутри сетевого
неймспейса, поэтому контейнер, который только программирует их, вынужден
занимать неймспейс хоста — а это не изоляция, а её отсутствие. Этот образ
вместо этого несёт резолвер и пропускает трафик сквозь себя, так что решает он
в том же неймспейсе, через который идут пакеты. Наружу не выходит ничего.

Отсюда единственное требование: **трафик должен идти через контейнер**.

## Что нужно на хосте

Ничего из того, что требует установка на хост: ни наборов, ни правил, ни
настройки резолвера — всё это внутри образа. Нужен только маршрут в контейнер.

**Своя машина.** Отдать контейнеру DNS и завернуть в него трафик:

```bash
# резолвим через него
echo "nameserver 172.30.0.2" | sudo tee /etc/resolv.conf
# и отправляем в него то, что он отберёт
sudo ip route add default via 172.30.0.2 metric 50
```

**Другие устройства.** Указать контейнер как DNS и шлюз — по DHCP или руками.

**Другие контейнеры.** Прицепить к его сети, и они получают сплит целиком:

```yaml
services:
  something:
    network_mode: "container:ladon"
```

## Куда уходит отобранный трафик

`LADON_EGRESS_GW` — адрес маршрутизатора, у которого уже есть туннель. Тогда
**свой туннель контейнеру не нужен**: он решает, что заворачивать, а несёт это
роутер.

Без этой переменной отобранный трафик уходит обычным путём. Это проверяет
работу механики, но ничего не говорит о туннеле.

## Запуск

```bash
docker compose -f release/docker/docker-compose.yml up -d
docker exec -it ladon /opt/ladon/ladon doctor
```

`doctor`, `status` и `why <домен>` работают в контейнере так же, как на хосте —
образ пробрасывает их напрямую. Полноэкранный вывод требует `-it`.

## Что отличается от установки на хост

- **Изоляция настоящая.** Наборы и правила — внутри. На хосте не появляется
  ничего, и снести их с хоста нельзя, потому что их там нет.
- **Первое соединение не теряется.** Резолвер стартует после того, как движок
  записал ему список доменов, поэтому адрес попадает в набор, пока пишется
  ответ — до первого пакета клиента. Перезапускать при этом нечего.
- **Права минимальные.** `NET_ADMIN` и включённый форвардинг. `privileged`
  не нужен, и файрвол хоста не затрагивается.
