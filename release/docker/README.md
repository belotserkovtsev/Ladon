# Ладон в контейнере

Образ несёт движок и готовые подборки. Всё остальное — наборы адресов, правила
файрвола, которые на эти наборы смотрят, и резолвер, чьи ответы ладон читает —
остаётся на хосте. Контейнер здесь про упаковку и обновление, а не про
изоляцию: сеть у него всё равно хостовая, иначе он программировал бы наборы, по
которым ничего не маршрутизируется.

## Что должно быть на хосте

Ладон не создаёт наборы и никогда не трогает файрвол — это сознательное
решение, оно не меняется от того, что он теперь в контейнере.

```bash
ipset create ladon_engine hash:ip  family inet -exist
ipset create ladon_manual hash:ip  family inet -exist
ipset create ladon_cidr   hash:net family inet -exist
```

Правила маршрутизации — по рецепту из [`docs/install.md`](../../docs/install.md).
Резолвер тоже хостовый: ладону нужен его лог, поэтому в dnsmasq должны быть
включены `log-queries=extra` и `log-facility`.

## Конфиг

Главное отличие от установки на хост: из контейнера не дотянуться до службы
dnsmasq, поэтому наполнение ручного списка ладон берёт на себя.

```yaml
# /etc/ladon/config.yaml
manage_dnsmasq: false
dns_freshness: 24h
```

Второй ключ здесь не косметика. Как только список наполняет движок, именно это
окно определяет, что в нём лежит: движок держит виденное за последние
`dns_freshness`, тогда как dnsmasq копил всё подряд. С дефолтными шестью часами
список получится в разы короче привычного. Подробнее — в
[`docs/configuration.md`](../../docs/configuration.md).

## Запуск

```bash
docker compose -f release/docker/docker-compose.yml up -d
docker exec ladon /opt/ladon/ladon -db /opt/ladon/state/engine.db doctor
```

`doctor` проходит по всему конвейеру и показывает первое порвавшееся звено.
Зелёный ответ означает «ладон в порядке» — если сайты всё равно не открываются,
причина ниже него: туннель, выход или сам DPI.

## Чем это отличается от установки на хост

- **Самое первое соединение к новому имени может уйти мимо туннеля.** dnsmasq
  успевал занести адрес в набор, пока отвечал на запрос; движок делает это сразу
  после того, как прочитал наблюдение. Дальше домен едет через туннель как
  обычно.
- **Список перестаёт расти бесконечно.** Обратная сторона того же: движок
  держит в наборе живое, а не всё, что когда-либо резолвилось. У `hash:ip` есть
  предел, и упереться в него неприятнее, чем иметь список покороче.
- **Команды оператора идут через `docker exec`.** `doctor`, `status` и
  `why <домен>` открываются на весь экран, поэтому им нужен `-it`.
